The compile button moves up into the PDF toolbar, leading the zoom cluster — the Overleaf-familiar spot: recompile top-left of the document, status to the right. It's one fixed 34×18 box: idle it's a green ▶, compiling it's a red ⊘ (click to stop) — glyph and color swap, the box never moves. An unsaved draft shows as an amber corner dot outside the box; ▶ always saves, then compiles, so the dot is a reminder, not a gate. Live: click ▶ to watch a build (bar + verdict), click the editor to dirty the draft.

1Cause meets effect. ▶ compiles the document you're looking at, in the bar that already owns that document's zoom, page № and verdict. The verdict keeps its right-anchor spot — the same handoff the real CSS documents for .pdfVerdict — so nothing shifts when a build starts reporting.
2The foot slims down. With ▶ gone, the editor foot keeps § outline · ◎ pdf and gains the fixed save chip (from 05): a constant-width saved · ⌘S box whose dot turns amber on a dirty draft — no sentence swap, no popping save button. The foot never reflows again.
·Semantics. ▶ = save, then compile (one press does what ⌘S-then-run did). On a live-watched doc the save alone triggers the watch's recompile — ▶ is then simply “save now”, and the staged bar + verdict report as they already do. Per-document: each ◫ pdf tab's toolbar carries its own ▶, so draft.tex and slides.tex stop sharing one button.
