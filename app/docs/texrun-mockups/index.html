Rethinking the LaTeX compile button five takes on where ▶ lives and how it holds still

Two complaints drive this series. Placement: ▶ compiles a document it can't see — it sits in the editor foot while the PDF and its ✓/✗ verdict live in the viewer toolbar, next to − fit ＋. Geometry: the button and its neighbors reshape at the worst moments — ▶ run swells into ⊘ stop run when you click it, and an unsaved draft swaps the save note for a longer sentence plus a materializing save button. Pages 02–04 move ▶ up beside the zoom cluster (the ask); 05 is the no-relocation floor. Every page is live — click the run control and the editor text to feel the states — and carries a measured state strip proving the geometry holds.

The geometry contract (shared by every proposal): every state of a control renders in the same box — glyph and color swap, width and height never do. Whatever can appear later (verdict, 🔧 fix, unsaved signal) either has its space reserved from the start or slides in from a right-anchor that shifts nothing — the handoff .pdfVerdict already documents in the real CSS. Unsaved state becomes an amber corner dot (toolbar variants) or a fixed-width save chip (foot), and ▶ always saves, then compiles — so “run before saving” stops being a trap that needs UI.
