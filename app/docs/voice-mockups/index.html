Design principles baked into these screens

Voice is I/O, not a new brain. Speech-in posts the same message route typing does; speech-out reads the same stream the console renders. The session, tools, permissions and rewind are untouched.

Push-to-talk, never always-on. Hold 🎙 or Space — the gesture Claude's own apps converged on. A lock gesture exists for long dictation; there is no wake word and no idle listening.

Speaking ≠ interrupting. Barge-in stops Claude's voice instantly but never the running turn; ⏹ stop remains the only interrupt. The two red lines of the dashboard (billed turns, tool side-effects) keep their existing controls.

Never read tool spew. Only assistant prose is spoken; code, tables and math get a one-phrase spoken summary. "Narrate progress" is opt-in for long runs.

Browser-native only. Recognition and replies both use the browser's built-in speech — zero setup, zero keys, zero new spend, zero new server surface. External voice engines are deliberately out of scope; the design leaves room to slot one in later if the built-in voices ever grate.

Color grammar reused: green = you/input (existing run-accent), purple = Claude's voice (the console's accent), amber = about-to-spend (the existing "needs you" color), red = interrupt.
