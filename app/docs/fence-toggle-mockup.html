raw | formatted — LaTeX fences in the console

scheme + design attempts · 2026-07-30 · no implementation yet
Feasibility: high, mostly assembled from existing parts. The raw display isn't an accident — katexEl() passes ignoredTags: ['pre','code',…], so fenced blocks are deliberately exempt from math typesetting. "Formatted" = take the fence's text and push it through the pipeline the console already uses for answer prose: md(text, {chat:true}) (marked + DOMPurify, style-forbidding) → katexEl(el, texMacrosVisible(project, task)) — which means the paper's own dialect (\E, \ah…) typesets correctly via the existing macro harvest, not as phantom-red unknowns. New code is: the toggle chrome, a per-fence state store, and a light structural pass for non-math LaTeX.

How it would work

  • Eligibility: the button appears only on tex-ish fences — lang tag ```tex/latex, or heuristic: ≥2 of $…$ / \begin{…} / \[ in the body. Julia/Python fences are untouched.
  • Formatted render: lazy on first toggle, cached on the segment. Math segments typeset via KaTeX; a small pre-pass handles the structure KaTeX can't: \emph/\textbf → styles, \begin{lemma|proof|remark} → labeled blocks, \label/\citet → dimmed chips. Everything else stays literal text — this is a reading aid, not a compiler; the pdf pane remains the ground truth.
  • State: per-fence choice keyed by a hash of the fence's content, stored in the task's console view state — NOT on the DOM node.
  • Default: raw. The fence is source; formatting is the opt-in.

Things to watch out for

  • Repaint survival: the console rebuilds segments on macro-harvest bumps, streaming re-segmentation, and renderWB — DOM-attached toggle state would silently reset. Hence the content-hash store, re-applied by the segment renderer.
  • Streaming tail: no toggle while the fence is still streaming (csRaw); it appears when the segment settles. A mid-stream toggle would typeset half an equation.
  • Sanitization: fence content is model output — the formatted path MUST go through the same DOMPurify profile as answer prose (it does, by construction, if md() is reused).
  • Copy: formatted view must keep the raw text one click away (copy icon copies the SOURCE, never the rendered HTML) — otherwise the toggle costs him paste-into-tex.
  • Macro drift: unknown macros still paint KaTeX-red; fine (consistent with answer math), but the harvest must use the task's pins (texMacrosVisible), not a global set.
  • Big fences: a whole appendix in one fence = hundreds of KaTeX nodes — render once, cache, and never re-typeset on scroll.
  • Honesty limit: alignment environments (align, custom numbering, cross-refs) will render approximately or not at all — the toggle should never claim pdf-fidelity.

Recommendation

  • Variant A. The header strip earns its pixels three ways: lang label (restores information the bare fence hides), the toggle where your eye starts, and a home for ⧉ copy-source. B is prettiest at rest but invisible to discover; C reads as an afterthought.
  • Scope v1 to math + the four common environments (equation, align→approx, lemma- family, proof); everything else literal. Ship the honesty footer ("approximate — compile for ground truth") only if testing shows people over-trust it.
