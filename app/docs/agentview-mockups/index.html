a Workflow is ONE task to the parent session — 18 inner agents, zero visibility. These variants climb a data-availability ladder (each page states what plumbing it needs):
variantshowsdata it needs
⑥ bannerone patching card: counters + latest summary nothing new — buildable today
⑦ phase pipelinestage strip w/ progress + live cards under the active phase phase + per-agent snapshot forwarded from the workflow
⑧ narrator timelinethe workflow's own log()/phase() lines, nested + timestamped narrator stream forwarded
⑨ sub-fleetthe fleet board nested in a workflow container (⑦+⑧+②) full inner telemetry
Claude's read: the shapes that survive all three states are ① and ②, and they compose: the roster strip is the always-on summary (count · running/done/failed · live verbs), and expanding it opens the fleet cards — phase-grouped when the team came from a workflow. ③'s nesting is worth stealing regardless: even with a strip, the agent lines that remain in the transcript should nest under their spawn line so post-hoc reading works. ⑤ is the most beautiful for exactly 2–4 agents and a dead end past that; ④ is the cheapest incremental fix if you want one afternoon's improvement instead of a redesign. Existing plumbing: session:agents already carries {n, type, desc, status, summary, tools, tokens} per agent — every variant here renders from data the dashboard already receives.
