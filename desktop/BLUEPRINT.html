Central Planner — Phase 1 Blueprint: the Desktop Shell

Phase 1 delivers a small Electron shell in a new top-level desktop/ folder — a physically separate construction with its own package.json — that is a pure client of the one Central Planner server. The launchd service (local.projectmanager, KeepAlive) remains the sole owner of port 4242: the shell attaches to a healthy running server and contains no code path that starts, signals, or races one. The spawn fallback drafted in rev 1 was removed by audit (desktop/BLUEPRINT_AUDIT.txt, 2026-08-07): no user-space pre-check can make it safe while the server runs its boot side-effects before binding the port — it is deferred to Phase 1.5 behind hard preconditions (§7), the first being the ~3-line server fix that defuses mis-spawns at the source. app/ takes exactly one deliberate diff: the two-line feature-detect that hides the mic button where speech recognition cannot work (§6 G1). The wins: a real window and dock identity, native notifications that fire even with the window closed, a single-instance lock, and no background-tab throttling. The browser at http://127.0.0.1:4242 and the phone PWA keep working at all times — unconditionally, since the shell never owns the server. This document is the binding contract, in the spirit of app/CONTRACT.md: what is written here is what gets built — three days, not weeks.

1Goals & non-goals

Goals (the contract's deliverables)

  • Own window + dock identity. A packaged (unsigned, ad-hoc) Central Planner.app with icon, Cmd+Tab presence, and notification attribution.
  • Native notifications. macOS banners for the same five moments app/lib/sessions.js pushes to ntfy — approval needed (session:permission), question asked and handoff recorded (task:update transitions — these fields never ride session:status; sessions.js stores them via updateTask()), sign-in needed and turn failed (session:status authNeeded/error) — driven by the shell's own persistent WebSocket to /ws. They keep firing with the window closed. Best-effort by design: the phone's ntfy push remains the guaranteed channel; on reconnect the state snapshot reseeds missed question/handoff banners, while an approval that fired into a dead socket cannot be reconstructed (pending permissions are absent from the snapshot — sessions.js:1792-1800). Documented, not hidden.
  • Single-instance lock. Relaunching focuses the existing window.
  • No throttling. backgroundThrottling:false so the SPA's 30 s heartbeat and 15 s WS stale-check run at full rate while hidden — the thing a browser tab cannot promise.
  • One-server rule, enforced by construction. Attach-only lifecycle: Phase 1 ships no spawn path, no child processes, no signals — there is nothing to get wrong. Quit never touches any server.
  • One deliberate app/ diff, zero others. The mic feature-detect (§6 G1 — two lines that also improve every non-Chrome browser). The server serves the whole frontend; the shell loads http://127.0.0.1:<port> and bundles nothing.
  • A shipped contract. desktop/CONTRACT.md carries the invariants, state table, probe rules, and cross-folder couplings; review gates on it like app/CONTRACT.md.

Non-goals (explicitly out of Phase 1)

  • Any other modification to app/. Two candidate diffs remain recorded, not taken (appendix C): the ~10-line runtime hashchange route for live task deep links (Phase 2), and the ~3-line server.js reorder (bind port before the stranded-task sweep; exit on listen error) — now the named entry precondition for Phase 1.5, not a Phase-1 change.
  • The spawn fallback itself. Removed from Phase 1 by audit findings F3/F4/F7/F19 (the TOCTOU race is un-closable from user space; packaged repo discovery is broken; lifecycle re-entry races; orphan hazard). Deferred to Phase 1.5 (§7) behind hard preconditions. Attach-only is a complete product on this machine — launchd attach is ~100% of launches.
  • Vite/TypeScript migration, Monaco, render-model rework (later phases). Code signing, notarization, dmg, auto-update (Phase 5).
  • Dock badge (designated first Phase-2 add, ~15 lines on the existing WS listener), dock bounce, tray item, global shortcuts, login item, always-on-top, multi-window, custom protocol handler.
  • Making dictation work inside the shell — Electron ships no speech-recognition backend; the mic button hides itself there (G1) and the browser + phone PWA remain the dictation paths. Replacing or replicating ntfy — phone push is untouched; desktop notifications are additive, local-only, and explicitly best-effort.
  • Windows/Linux. The lifecycle is deliberately launchd-specific; darwin only.
  • Pidfiles, orphan adoption, auto-respawn budgets, DEGRADED health telemetry — cut with the critics (over-built for a machine where launchd is the ~100% case; adoption was the portfolio's only kill-what-you-didn't-spawn vector).
  • Any preload script or IPC surface. The renderer is exactly a browser tab; connecting.html is static.
  • Telemetry, crash reporting, external resources of any kind (public repo; hard no-CDN rule).

4Main-process architecture: the state machine

The rule above all rules: the shell never starts, signals, restarts, or port-races any server. Phase 1 contains no spawn path — attach, wait, or refuse are the only verbs. And one coordinator: every lifecycle trigger (startup, did-fail-load, wake, retry) joins the single active reconcile loop; none starts a second (invariant I8).

The eight invariants (verbatim into CONTRACT.md)

  1. The shell never starts, kills, restarts, or signals any server process, and never mutates launchctl state — Phase 1 contains no code path that sends a signal or spawns a child.
  2. Phase 1 ships no spawn path. The lifecycle's only verbs are attach, wait, and refuse; the spawn fallback exists only in Phase 1.5, gated on its five preconditions (§7).
  3. Exactly one notifier WebSocket exists at any time, with reconnect backoff capped at 5 s→60 s and a 60 s silence watchdog; HTTP probing uses only GET /m/manifest.webmanifest; POST /api/heartbeat, /api/state-as-probe, and WS-connect-as-ping are forbidden.
  4. The renderer holds zero privileges: no preload, no IPC, sandbox + contextIsolation on; permission check and request handlers deny by default, allowing only origin-pinned, main-frame clipboard-sanitized-write; all window-opens denied, with http/https/mailto routed to shell.openExternal and every other scheme dropped and logged.
  5. No menu item ever binds an accelerator in Cmd+0..5; resetZoom lives on Cmd+Shift+0.
  6. A live SPA is never reloaded by the shell; intervention happens only on main-frame, filtered did-fail-load (§2); close hides silently, and the draft dialog fires only on paths that actually unload (reload, quit).
  7. http://127.0.0.1:<port> in a browser and the phone PWA behave identically before, during, and after the shell runs — unconditionally, since the shell never owns the server.
  8. At most one lifecycle reconcile loop is active at any moment: every trigger (startup, did-fail-load, wake, retry) joins the current generation or is dropped; a superseded generation's callbacks are inert.

Cross-folder couplings — the FULL inventory (audit F15), recorded in CONTRACT.md with the same-commit-update + re-pack rule (F16): (1) port precedence & CP_ROOT config discovery (app/lib/config.js:21-24, :50); (2) m/manifest.webmanifest's name === "Central Planner"; (3) launchd label local.projectmanager; (4) the notifier's event names + payload shapes (session:permission(:resolved), task:update, session:status, the state snapshot); (5) init-only hash routing (app.js:10240-10253); (6) Cmd+0..5 page bindings; (7) the beforeunload draft guard; (8) Node ≥ 20; (9) the 25 s WS tick (events.js) the watchdog times against.

8Test plan

Smallest meaningful, matching the repo's node --test culture. The shell's safety-critical core is a pure decision table with two injectable inputs — that is what gets automated. Billing safety is trivial: the shell never calls any /api mutation route (CP_NO_BILLED spirit honored by construction).

  • test/lifecycle.test.mjs (node --test, no Electron runtime — serverlink.js takes its probe/launchctl/ws/clock functions as injectable deps):
    • Decision matrix: probe ∈ {HEALTHY, FOREIGN, REFUSED, TIMEOUT} × launchctl ∈ {loaded, not} → asserted states {ATTACH, WAIT_LAUNCHD, SERVER_ABSENT, BLOCKED/OCCUPIED}; no input combination reaches a spawn — there is none to reach.
    • Notifier event map (the F1 regression, pinned forever): against a scripted fake WS feed — session:permission banners once and clears on :resolved; a task:update question null→text banners, same-text again doesn't, a later different question does; handoff newly set banners once; session:status error/authNeeded banner; question/handoff keys appearing on a session:status payload are IGNORED.
    • Reconciliation + persistence: a snapshot containing an unnotified waiting question fires exactly one banner; restart with the same persisted notify-state fires none; an approval absent from the snapshot never resurrects (best-effort, documented).
    • Watchdog + backoff: a silent socket > 60 s (fake clock) → terminate + reconnect; a flapping stub server → ≤ N connects/minute (fails if the cap is ever removed).
    • Single-flight: concurrent triggers (startup + did-fail-load + resume) yield exactly one reconcile loop; a superseded generation's completion is inert.
    • Filters + parsing: did-fail-load with isMainFrame:false or ERR_ABORTED → no intervention; port values "abc"/0/70000 fall through with a log; identity probe classifies wrong-name / 404 / non-JSON as FOREIGN; off-screen saved bounds re-center.
  • Manual smoke matrix lives in CONTRACT.md, not CI (packaged-app concerns can't be automated cheaply): packaged banner + codesign verify (day-2 gates), Cmd+0..5, draft-guard on reload/quit, close-hides-silently, sleep/wake notify, kickstart mid-use, foreign squatter, SIGSTOP/SIGCONT probe classification, battery measurement, localStorage first-run note.
  • Non-goals: no Playwright/Electron-driver harness, no UI screenshot tests, no billed-route exercise of any kind.
